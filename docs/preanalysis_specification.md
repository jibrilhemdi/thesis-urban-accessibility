# Pre-analysis specification — version 1, frozen 2026-09-29

This specification is fixed **before price-model fitting**. It governs the current Inside Airbnb Copenhagen snapshot (file snapshot 2026-06-30; source `last_scraped` spans 30 June–4 July), official study geography, and Phase 5–6 canonical OSM destination set. Changes require a dated decision-log entry and must be identified as post-freeze deviations. PostgreSQL/PostGIS tables and migrations, not exported CSVs, are authoritative.

## Population and outcome

- Study geography: Copenhagen and Frederiksberg. Phase 2 population requires `in_study_area`, `room_type='Entire home/apt'`, one of the six predeclared conventional types (`Entire rental unit`, `Entire condo`, `Entire home`, `Entire townhouse`, `Entire villa`, `Entire loft`), valid coordinates and valid **positive** source price. No review or availability restriction. All excluded listings remain in `analysis.analysis_dataset_v1` with flags.
- Outcome: `log_price = ln(price_nightly)`, source listed nightly price treated as DKK by user confirmation. The source itself displays `$` without an explicit currency code. This is a listed offer, not a transaction or booking. No price imputation or replacement by scrape date. The observed `last_scraped` date is provenance, not a price-selection rule or main-model covariate.
- The Phase 2 primary candidate count is **12,521**. Official geography is assigned to **12,508**. The fixed common model-comparison set is the **12,412** candidates with an official area and a reachable walking station. The other 13 official-area gaps and 96 disconnected-station cases remain in the analytical view and all-listing diagnostics. No path is invented for them. An opportunity-count-only sensitivity may use 12,508 assigned candidates and must explicitly omit station time from *every* compared specification.
- Of 21,080 conventional entire-home listings before price selection, 8,559 (40.6%) have missing/invalid price. Overall, 9,284/23,144 (40.11%) do. Analyse this selection; never fill it. No assumption that price observation is random.

## Geographic and contextual interpretation

Official municipalities (EPSG:4326 source, EPSG:25832 metric analysis) and ten City `bydel` polygons plus Frederiksberg as **one municipality-sized CV/context proxy** are separate from Inside Airbnb provider polygons. The City StatBank district code and district name agree with the numbered official districts (including `/` versus `-` in district 4), but the WFS polygon **vintage remains unverified** against the statistical reference geography. The view labels this explicitly. The 2026-Q3 population figures postdate part of the listing scrape; 2024 income is older. Frederiksberg national income has a different denominator/producer from the City's district income. The view therefore exposes district and Frederiksberg-municipality values in **separate columns**; they are never pooled as one harmonised neighbourhood feature.

Primary location controls are official municipality (category) and projected straight-line City Hall Square distance (km). District fixed effects are a sensitivity, not combined with municipality effects or district-constant context in the same explanatory specification. District income/population can enter a **Copenhagen-only exploratory sensitivity** only after the boundary-vintage/crosswalk caveat is retained; results represent associations with 10 area-level values, not 11,203 independent incomes. Do not use an unverified land-area denominator or claim population density. Frederiksberg context remains municipality-level descriptive. No GTFS features enter this freeze while approval/data are pending.

## Primary controls and missing-data decision

Property block, fixed without examining price associations: six-level property type, `accommodates`, `bedrooms`, `bathrooms_effective`, `log1p_minimum_nights`, `superhost`, `log1p_host_listings_count`, and eight exact-token amenities selected in Phase 2 before price modelling: Wifi, Dishwasher, Washer, Dryer, Dedicated workspace, Free parking on premises, Private patio or balcony, Self check-in. Treat property type as categorical. The bathrooms variable uses the structured field first and, only where absent, a numeric or `Half-bath` value **parsed from the same source listing text**; its provenance flag remains visible. One structured/text disagreement retains structured precedence and is audited.

`bedrooms` is missing for 124/12,521 (0.99%). For cross-validated prediction, use training-fold median and a missingness indicator; fit both inside each training split. Report complete-case OLS as a sensitivity, with a common evaluation set for model comparisons. No database NULL is overwritten. The source-based bathroom fallback leaves no missing `bathrooms_effective` in the primary candidate sample. All eight selected amenities and the other primary property controls are observed in the current candidate sample. `instant_bookable` is entirely missing, so it is **excluded**, not filled. Raw `beds` is missing for 1,291/12,521 (10.31%) and strongly tracks `accommodates`/`bedrooms`; retain it for diagnostics, not primary modelling. Review counts/ratings are secondary activity/quality-proxy robustness controls; ratings are missing for 1,911/12,521 (15.26%) and must not silently restrict the main sample.

If an explanatory robustness specification requires a materially missing predictor such as rating, specify complete-case and training-only proper multiple imputation (MICE) as **separate sensitivity analyses**, with imputation uncertainty reflected in OLS inference; do not choose between them by outer-test performance. XGBoost may use native predictor missingness in its own predeclared sensitivity. Neither TabPFN nor TabICLv2 is part of this freeze; TabICLv2 is not an imputer. The outcome is never imputed.

## Accessibility definitions and model ladder

Use the **same Phase 5 deduplicated** food/social (restaurant/cafe/bar/pub), cultural/tourist, and rail/metro station destinations. Euclidean distances/counts use EPSG:25832. Walking paths use the versioned Phase 6 directed pedestrian graph, EPSG:25832 edge lengths, 4.8 km/h, and both listing/destination snap connectors. Primary opportunity comparison is straight-line **800 m** versus network **10 minutes** (800 m route budget). Predeclared sensitivities are 1,200/1,600 m versus 15/20 minutes. Straight-line radius is not a walking isochrone. Do not change POI categories or thresholds based on price-model results.

All models use the same 12,412-row common set for their primary predictive comparison:

1. P: property block above.
2. P+L: add municipality and City Hall Square distance.
3. P+L+E: add Euclidean nearest-station distance (km), `log1p(food_social_800m)`, and `log1p(cultural_tourist_800m)`.
4. P+L+W: replace those three accessibility terms with continuous nearest-station walking minutes, `log1p(food_social_w_10)`, and `log1p(cultural_tourist_w_10)`.

Do **not** put E and W counts together in the primary explanatory model: the corresponding food counts have Spearman 0.952 and cultural counts 0.914, with large combined-model VIFs. The core comparison is the predictive increment beyond P+L and whether W improves over E on the same held-out listings. A separate descriptive OLS analysis may estimate alternative specifications and discuss spatially correlated residuals; these are associations, not causal effects.

Fit semi-log OLS with heteroskedasticity-robust HC3 intervals for association, Elastic Net as a regularised comparator, and XGBoost for prediction. Model families are predeclared, not selected by headline performance. Tune only on training portions of the outer folds. Categorical encoding, imputation, missing indicators, scaling, feature transformation that learns parameters, and hyperparameter selection belong inside training-fold pipelines. XGBoost's native predictor missingness may be compared only as a labelled sensitivity. No feature or amenity is selected by p-value.

## Spatial validation and reporting

`analysis.spatial_cv_folds_v1` freezes 1-km EPSG:25832 projected grid blocks, using all **23,066** officially assigned listings and no price or accessibility value. Five outer `StratifiedGroupKFold` splits group whole grid cells, stratify on official municipality, shuffle with seed **20260929**, and retain both municipalities in every fold. There are 111 unique grid blocks. The persisted fold assignment is never automatically overwritten. This controls exact within-block leakage but does not guarantee a kilometre of separation across adjacent train/test blocks or equal fold size. Spatially adjacent block leakage and unbalanced fold sizes are limitations. For tuning, use four inner municipality-stratified grouped folds on the outer training blocks only, seed **20260930**; if four splits fail a training-only feasibility check, report the issue before fitting rather than falling back to random rows. Do not use an outer test fold to choose tuning ranges or preprocessing.

Report pooled out-of-fold log-price RMSE, MAE and R² for every ladder step and model family; also report fold-level metrics and sample counts. Discuss the E/W versus P+L change and uncertainty, not just the best score. Predicted price on the original scale, if shown, needs retransformation-bias handling and must be secondary. No validation fold is an independent causal experiment.

Predeclared robustness: 15/20-minute versus 1,200/1,600-m opportunity thresholds; opportunity-count-only 12,508 sample; Copenhagen-only; exclude Frederiksberg; near-border exclusion; one-percent extreme-price trimming with cutoffs learned **inside each outer training fold** before applying the same bounds to that fold's test records; complete-case bedrooms; and exploratory Copenhagen-only context after vintage caveat. Review counts/ratings enter separately as secondary proxies, never a primary sample restriction. Diagnose residual spatial autocorrelation (e.g. Moran's I) **after models are fitted**, without using outer test data to revise the model ladder. Calendar availability/minimum-night restrictions and review activity remain secondary outcomes/proxies, never occupancy, bookings, or realised demand.

Public analysis tables/maps must be aggregate-only: no listing IDs, host names, free text or row-level point coordinates. The private PostGIS analytical view includes listing IDs solely for reproducible joins; no point geometry is exported by this phase.

## Phase 8 CV addendum — user-authorised before any model fit

The Phase 7 primary five-fold 1-km spatial assignment and 12,412-row common model-comparison set **remain unchanged**. Phase 8 adds fixed outer schemes in `analysis.cv_assignments`: random five-fold (seed 20260929) as a spatial-leakage benchmark; 11 leave-one-official-area-out folds (10 Copenhagen districts and municipality-sized Frederiksberg); and a 1.5-km five-fold geometric-block sensitivity (seed 20261034, selected using municipality/group sizes only). Persisted 500 m and 1,000 m EPSG:25832 held-out-area buffer exclusions are candidate geographic robustness designs. They are not selected based on model performance. No LOAO area is merged: the smallest common-sample held-out group has 221 listings. The Frederiksberg LOAO fold contains a municipality category unseen in its training set; this extrapolation must be reported explicitly. Later comparable models must reuse these exact stored outer assignments and identical common-sample rules, with preprocessing/tuning confined to each training split. See [the Phase 8 report](../reports/phase08_eda_and_cv.md) for fold counts, weights, support and buffer feasibility. This addendum supplements the original freeze because the user requested new diagnostic CV schemes before final modelling; it does not retroactively relabel them as the original primary split.

## Bus-access robustness amendment — 2026-09-29, before Phase 9

Prior to final model estimation, simple bus-stop proximity will be added as a secondary transport-accessibility measure because previous Airbnb research explicitly considers bus access. It is excluded from the primary accessibility specification because proximity to an individual bus stop does not account for service frequency, route connectivity, waiting time, or reachable destinations. If timetable GTFS becomes available, bus services will instead be incorporated into multimodal schedule-sensitive transit accessibility.
