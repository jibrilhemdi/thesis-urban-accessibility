# Scientific freeze and presentation versioning

The empirical science is identified by the immutable `scientific_manifest.json` in `outputs/releases/2026-09-30_scientific_freeze_v1/`. PostgreSQL/PostGIS remains the authoritative persistent analytical layer; the release archives read-only provenance and machine-readable results, **not** private Airbnb raw rows or a database dump. The old Phase 10 `primary_freeze.json` is retained as historical integrity evidence, but its PNG hashes do not make pixels scientifically immutable. See [the freeze record](../outputs/releases/2026-09-30_scientific_freeze_v1/SCIENTIFIC_FREEZE.md) and [final synthesis](../reports/final_scientific_synthesis.md).

## Allowed post-freeze presentation changes

Colours, fonts, sizes, line widths, marker sizes, transparency, legends, map labels, titles/subtitles, captions, annotations, panel arrangement, figure dimensions, DPI and PNG/PDF/SVG export may change. Table column widths, orientation, LaTeX formatting, line breaks, table notes, thousands separators, displayed decimal precision, main-text/appendix placement, terminology clarification and accessibility/readability improvements may also change **when the scientific meaning and underlying frozen values remain the same**. A presentation script may regenerate a figure or formatted table from frozen machine-readable results; it must not refit a model, recompute a feature or rewrite a frozen result source.

For display axes, use clear ticks, correct transformation notation and common scales only where comparisons are legitimate. Disclose display-only truncation (for example, a P99-only plotted range) without dropping observations from analysis. Do not hide inconvenient observations, alter analytical transformations, manipulate scales misleadingly, manually replace numerical values, or omit data to improve a visual conclusion.

Preferred lineage is `frozen machine-readable results → presentation code → PNG/PDF/SVG` and `frozen machine-readable tables → LaTeX export → thesis typesetting`. `make final-presentation` verifies the scientific hashes before and after running only the aggregate final-output revision and LaTeX exporters. The validation-design schematic is synthetic; the actual block map is reconstructed from saved assignments by the separate read-only `make validation-visuals` command. The public OSM boundary illustration is generated by `make boundary-catchment-figure`; neither command fits a model. Do not use a broad phase/rebuild target for a styling edit. Some original phase plotters still embed display-only palettes, layout positions, thresholds for viewports and labelled rounded numbers; these should be checked against the frozen source tables when restyling, not treated as a second scientific source of truth.

## Changes requiring a new scientific version

Any change to sample membership, outcome or price treatment, geographic/study-area eligibility, destination taxonomy or canonical IDs, buffered opportunity universe, accessibility thresholds, walking speed, snap/routing logic, CV assignments/block size/buffer distance, predictor set, transformations, socioeconomic variables, missing-data treatment, model family, hyperparameters, tuning rules, estimation seeds, or addition of a substantive model/robustness analysis requires a documented `scientific_freeze_v2`. Selecting an alternative specification because it scores better also requires a new scientific version; it cannot silently replace v1.

If a genuine scientific error is found, preserve v1, log the defect and affected artifacts, decide the selective recomputation required, compare old/new numerical results and claims, then create v2 only with explicit user direction. Do not edit v1 in place.

## Presentation releases and error classes

Future styling releases are separate from science, for example `outputs/presentation/YYYY-MM-DD_v1/`, `YYYY-MM-DD_v2/` or `YYYY-MM-DD_submission/`. Each should contain `presentation_release_id`, `scientific_source_release`, creation time, Git commit and a short change log (for example palette, caption, legend, Table 8 layout or LaTeX orientation). No scientific model may run as part of that release. A presentation release can be rebuilt from the frozen scientific source; its pixels need not match the freeze-time snapshot.

1. **Presentation/typo error:** fix the layout/wording, record the presentation change; v1 science remains valid.
2. **Presentation data-link error:** if a chart selected the wrong frozen metric column but its source results are correct, fix the presentation and record the correction; v1 science remains valid.
3. **Scientific implementation error:** if the sample, feature, destination universe, fold, model metric or data processing is wrong, stop and create a documented scientific v2. Do not silently modify v1.

The [final claim document](final_claims_for_thesis.md) and [claim matrix](../outputs/tables/conclusion_stability.csv) constrain interpretation as well as numbers: later wording must not reverse the substantive RQ2/RQ3 conclusion while calling the work presentation-only.
